# 一期优化执行方案

## 已确认目标

先修复一期可靠性问题。Markdown 改用成熟解析与高亮库；所有登录读者可评论，提交后待审核；管理员可审核全部评论，文章作者可审核自己文章下的评论。

本文件记录已确认的实施范围；一期已实施，实际结果见 [一期优化验收记录](一期优化验收记录.md)。验收使用现有 Docker Compose 环境，当前本地入口为 http://localhost:30080/。

## 1. Markdown 渲染

- `frontend/package.json`、`frontend/package-lock.json`：引入 Markdown 解析、高亮及任务列表支持所需依赖；实施时核对官方接口与版本，提交锁文件。
- `frontend/src/utils/markdown.ts`：替换手写块解析和正则高亮，保留 `renderMarkdown`、`renderMarkdownDocument`、`extractToc` 及现有返回类型。
- 原始 HTML 按文本处理；链接和图片 URL 做协议校验，禁止脚本协议。外链保留必要的安全属性。
- 保留表格、任务列表、图片、引用、代码语言标识和 h2/h3 目录。目录由解析结果生成，排除代码块内的伪标题；标题锚点在同一篇内唯一，并尽量兼容现有锚点规则。
- 未知代码语言退回转义后的普通代码；按需注册语言，避免引入完整高亮语言包。
- `frontend/src/styles/global.less`：适配高亮类名，保留当前代码块、表格、任务列表的视觉效果。
- 核对 `ArticleDetailPage.vue` 和 `ArticleEditorPage.vue`，确保详情与编辑预览使用同一渲染入口。

验收：`|hello|` 正常返回；JavaScript `const x = 1` 的文本与 HTML 结构正确；表格、任务列表、中文/重复标题、围栏代码块中的标题、空文档可正常处理；原始 HTML 和危险 URL 不执行。卡死回归用独立进程/worker 超时保护。浏览器检查现有文章及编辑预览样式。

## 2. 评论提交与审核

现状：提交评论继承了文章写作权限，读者 POST 被拦截；审核仅有 Django Admin 入口，普通作者没有可用审核界面。

- `backend/apps/content/views.py`：将评论提交权限与文章编辑权限分开；匿名可查看公开文章的已通过评论，登录用户可对公开文章提交评论，不能绕过草稿可见性限制。
- 评论提交继续使用 `POST /api/v1/posts/{id或slug}/comments/`，正文 `{ "body": "评论内容" }`。成功返回 201，服务器固定 `approved=false`，忽略或拒绝客户端越权审核字段。
- 管理员及该文章作者可以查看该文章待审核评论；其他访问者只能查看通过的评论。
- 新增嵌套审核接口 `PATCH /api/v1/posts/{id或slug}/comments/{comment_id}/`，正文仅接受布尔字段 `{ "approved": true或false }`，返回更新后评论。校验评论属于路径文章，并在服务端校验审核者身份。允许通过及撤回公开，不提供删除功能。
- `backend/apps/content/serializers.py`：增加受限审核输入契约；评论正文不通过该接口更改。
- `frontend/src/api/posts.ts`、`frontend/src/types/index.ts`：接入审核契约；审核能力由后端返回的文章级能力字段表达，不能仅靠前端角色判断。
- `frontend/src/views/ArticleDetailPage.vue`：为有权限者显示待审核标记和“通过/撤回公开”按钮；显示请求中和失败反馈；普通读者保留提交成功、等待审核提示。
- `backend/apps/content/admin.py`：保留现有管理员入口；本期不扩大 Django Admin 授权范围。

验收矩阵：匿名提交被拒绝；普通读者提交成功且公众不可见；文章作者及管理员可以查看并审核；其他作者/读者不可审核；伪造文章与评论组合不可越权；撤回后公众不可见；审核接口不能修改正文、作者或所属文章。文章编辑权限保持原规则。

## 3. 密码重置链接

- `backend/apps/accounts/views.py`：从配置 `FRONTEND_BASE_URL` 拼接重置链接，不使用请求 Host 推导前端地址；规范末尾斜杠，并保留 token 参数。
- `docker-compose.yml`：将 `FRONTEND_BASE_URL` 传入 backend，默认值与本机 `WEB_PORT` 对应；生产部署可显式设置外部 HTTPS 地址。
- `.env.example`、`backend/.env.example`：补充配置说明，分别覆盖 Docker 和前后端分端口运行。
- `docs/deploy.md`、`docs/api.md`：同步外部地址配置、评论权限和审核接口说明。
- 保留一小时有效期、一次性 token 及不泄漏邮箱是否注册的响应方式。

验收：不同请求 Host 不改变邮件目标站点；配置末尾有/无斜杠均正确；有效 token 可以重置，过期、无效及使用过的 token 被拒绝。自动测试使用内存邮箱，不向真实邮箱发信；真实 SMTP 投递不列为本期已验证项目。

2. 在 `backend/apps/content/tests.py` 补齐评论权限矩阵，在 `backend/apps/accounts/tests.py` 补齐邮件目标地址及 token 边界测试。
3. 执行前端测试和生产构建、后端全部测试。现有基线为后端 19 项通过，前端构建通过；实施后记录新增后的实际数量。

5. 浏览器验证文章渲染、编辑预览，以及读者提交→作者/管理员审核→公众可见→撤回的流程。写入验证使用独立测试数据库与测试账号，不改动现有文章。
6. 记录实际命令、结果和未验证范围；测试失败不报告为通过。交付改动说明及回滚方法。

## 范围和回滚

本期不处理收藏/草稿分页、本地草稿恢复、全站移动端改版、生产种子数据默认值、独立评论管理后台。预计不需要数据库结构迁移。

回滚以本期代码及锁文件对应版本重建镜像；保留数据库与媒体卷，不执行 `docker compose down -v`。评论审核状态属于业务数据，代码回滚不会自动恢复之前状态。
